# 课程与反馈设计

生成纲要、单节课程、错题讲解或下一步建议时使用。来源规则和状态权限以 [SKILL.md](../SKILL.md) 为准。

## 把目标拆为可学习的单元

先确定学习者最终需要完成的任务，再倒推必要知识。区分必须先学的内容与可选拓展，让课程顺序能解释“为什么现在学这一课”。

每个单元描述：

- 一个能观察的学习结果，例如解释一种机制、完成一次计算或识别一个错误。
- 必要前置知识；不把未确认的基础当作已经掌握。
- 预计所需时间，以及可用于检查理解的活动。
- 资料模式的依据与覆盖缺口；主题模式中需要后续核验的内容。

已有资料目录是组织线索，不必机械地一章对应一课。长章可以拆成几课，跨章的重复概念可以合并，但要保留出处。

一次检索返回的少量片段用于设计对应单元。需要整份课程时，先查看完整可用目录与覆盖范围；部分解析、未读取章节或缺页应体现在课程范围说明中。

用户指定的时间不足以覆盖全部目标时，给出可完成的核心范围和可选拓展，并说明取舍。不要承诺固定天数后必然掌握。

## 一节短课的组织

1. **目标与连接**：说明本课解决什么问题，以及与上一课或学习目标的关系。
2. **简明讲解**：先给直观解释，再给必要定义、条件或步骤。首次使用术语时解释它。
3. **示例**：演示一次思考过程。计算题展示关键中间步骤，机制题可使用对比或反例。
4. **理解检查**：先让学习者回忆、判断或解释；不要在问题旁立即泄露答案。
5. **反馈与下一步**：回答后给针对性反馈，根据表现继续、补讲或安排练习。

这是一种默认组织方式。用户只问一个局部问题时，给对应讲解，不强制输出整个课程模板。

同一个概念可以提供“更直观”“换个例子”“更深入”的讲法，但不能只增加字数。资料模式中的新示例应标明为教学构造，并且不改变资料支持的结论或适用条件。

可选的速查内容包括术语表、公式、步骤清单或代码片段。只保留会再次使用的内容，不为每一课生成大量重复附件。

## 练习与评分

| 学习目标 | 可选检查方式 |
| --- | --- |
| 辨别概念、条件或误区 | 单选、多选、判断 |
| 不看原文回忆核心事实 | 填空 |
| 应用公式或进行计算 | 数值题 |
| 解释机制、比较方案或说明原因 | 短解释 |

题型不等于难度。根据学习者的回答调整条件数量、提示量和迁移程度，不只替换“简单 / 困难”标签。

对话内的一道理解检查题可以独立使用。创建网站练习时须遵守实际契约，不能假定一个接口同时支持六种题型。

选项尽量自然且信息量相近，避免正确选项总是最长或表达最完整。生产环境的选项打乱由受控组件处理，并保持正确答案与选项身份对应；不要声称提示词能够保证随机性。

展示提示前说明它属于辅助作答。提示由轻到重：定位相关概念、提醒条件、给出部分步骤；根据用户请求再展开完整答案。

面向学习者的未作答页面仅包含题干、选项和必要条件。标准答案与评分细则交给现有受保护的题目和评分流程，不能放进公开课程 JSON 或可直接读取的前端数据中。

## 反馈要基于本次表现

将“观察”与“推测”分开：

- 观察：“你的答案给出了结论，但没有说明题目中的前提条件。”
- 推测：“可能忽略了这个条件；可以用下面的问题确认。”

反馈先指出有效部分，再定位缺失，随后给出解释或一个更小的练习。不要仅凭一道题判定用户长期能力，也不要把随口的肯定回答当成掌握证据。

保留用户回答的原意，不能替用户补全推理后再宣称其答对。无法确认短解释是否满足要求时给出教学建议或待复核提示，不自行生成确认评分。

## 初始摸底与后续安排

需要选择起点时，可以用少量代表性问题摸底。样本只能支持有限的起点建议，未覆盖的概念继续标为未知；不输出未经校准的“掌握率 90%”。

后续任务综合考虑：

- 服务端已返回的到期复习及暂停状态。
- 当前单元未解决的理解问题。
- 新单元的前置要求、用户目标和剩余时间。
- 作答是否独立、评分是否确认、题目是否重复。

一个可执行的任务应说明学什么、为什么、预计多久，以及结束后检查什么。已经由服务端确定的复习时间与阶段不能被教学模型覆盖。

复习优先使用不同表述或新的应用情境，区分记住原题和理解概念。不要将当天重复答对自动解释为长期保留；沿用项目已有的独立证据和复习规则。

## 暂停与续学

有课程上下文时保存并沿用课程版本、当前单元、已生成内容和未完成检查。用户说“继续”时，从这些事实中定位下一步。

没有可读取的记录时，说明当前缺少哪门课或哪个单元的信息；不要编造“上次已经完成第三课”。用户提供的回忆可作为自我报告使用，但与系统确认的作答记录分开。
