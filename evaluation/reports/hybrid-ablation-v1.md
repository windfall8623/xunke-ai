# 中文混合检索与重排：待运行说明

日期：2026-09-08。**真实模型消融尚未运行，本文件不是改善报告。** 中文词法、RRF、有界重排、结构分块和覆盖规划已有实现及可控服务测试；真实效果、模型资源占用、p95 和有效题成本仍需按以下协议测量。

## 预定比较

| 对比                              | 控制因素                                      | 待验证问题                           |
| --------------------------------- | --------------------------------------------- | ------------------------------------ |
| dense 与 `bm25-v1`                | 同一冻结资料、query/scope、证据预算和评分规则 | 中文术语、数字和混合语言的召回差异   |
| dense 与 `hybrid-v1`              | 同一 build/Embedding，关闭查询扩写            | RRF 是否改善证据组覆盖及完整证据召回 |
| `hybrid-v1` 与 `hybrid-rerank-v1` | 相同初始候选集                                | 重排质量是否抵消新增延迟和费用       |
| 无重排、BGE、Qwen 候选            | 每次显式固定 endpoint/model/revision/许可证   | 哪个实际部署方案满足资源与发布门槛   |
| 普通块与 `structure-v1`           | 固定模型/资料/预算，记录实际 build 差异       | 结构块和父段是否减少证据缺失         |
| 固定分块下关闭/开启覆盖规划       | 仅在配置能够单独控制时比较                    | 多目标/多章节出题的覆盖收益          |

注册方案及可用性来自 [pipeline registry](../../backend/app/rag/registry.py) 与 [评测 API 服务](../../backend/app/services/evaluation_service.py)，不能在网页中提交任意模型地址。BGE/Qwen 是待配置评估的候选，不表示项目已下载、部署或比较过其真实权重。如果某候选同时改变分块、检索和覆盖规划，只能标“端到端方案比较”，不能把收益归因于一个因素。

## 执行和判断

先完成真实 B0 与 [B1](llamaindex-parity-v1.md)、人工数据冻结和适用 judge 校准。在 dev 选择候选、冻结协议后再使用 locked-test。保存相同 sample_id/repeat_index 的全部结果和失败，不挑最好一次。各路检索、重排和父段扩展必须保留完全相同的授权白名单；降级使用 RRF 时应按实际 effective_config 报告，不能算作重排成功。

默认证据上下文上限为 6000 token，包含包装和引用 ID。分别报告 EvidenceGroupRecall、AllEvidence、有效题产出、来源/答案支持、完整套题、拒答/无依据出题、unknown/error、调用与费用，以及记录硬件/并发后的冷/热、队列/执行 p50/p95。跨分块指标遵守 [评测说明](../README.md)，不能把候选块数直接当作可比真值单位。

按连通文档家族簇做配对 bootstrap，保持原指标分母；正式判定遵守 [门槛配置](../configs/release-gate-v1.json)。不足独立簇、未校准或未裁决情况只能作探索判断。较慢、费用超限或来源质量退步的候选不能只因平均召回提高而默认启用。
